# Changelog

New changes go under `[Unreleased]` and get a version number when a release is cut. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [SemVer](https://semver.org/): a new skill bumps MINOR, a change that alters a skill's expected behaviour bumps MAJOR, anything else bumps PATCH.

## [Unreleased]

### Added

- `skill-tune` skill: records what an installed skill did wrong in a local findings log, sorts it into a project rule, a defect or a personal variant, fixes the local copy with an approved diff and marks it `tuned`, and verifies the fix by repeating its case and the skill's other evals; updates a tuned copy to a new version with a three-way merge from a saved base, asking on each conflict; drafts an issue per defect or one summary issue, published only on approval. Never weakens a Never rule or edits the skills repository. Five evals on the sandbox `trunk` scenario.
- `eval-finding` issue form, so findings arrive with the skill, agent, case, fix and result.
- `install.sh --force`: `--update` now skips copies tuned with `skill-tune`; `--force` replaces them and drops their saved state.
- `release` skill: prepares a release following the repository's flow (an optional `Release:` rule, or deduced and confirmed once) and versioning rules, with a script that reports the last version, the `[Unreleased]` section, the commits since, the version files and diverged branches; proposes the version for the user to confirm, closes the changelog, opens the release pull request with notes, and after the merge gives the tag commands and opens the back-merge. Never tags, publishes or merges. Four evals on the sandbox `release-*` and `integration-dev` scenarios.
- `security-pass` skill: a focused security review of the current change, using the scanners the repository declares (found by a script) or a temporary run the user accepts, a checklist read only for the categories the diff touches, and each new input followed to where it is used; reports verified findings with a masked secret and a concrete fix, and prepares a scanner integration to apply on approval. Five evals on the sandbox `security` scenario.
- `new-adr` skill: records a decision as a numbered ADR (context, options, decision, consequences) in the repository's own format and folder, found by a script that also gives the next number; writes `Proposed` unless the user says it is decided, updates the index, and marks a replaced record `Superseded by` without touching the rest of it. Four evals on the sandbox `adr` and `trunk` scenarios.
- `install.sh`: copies all or some skills, without their `evals/`, into a project's `.agents/skills/` or `.claude/skills/`, skips installed ones unless `--update` is given, and points to `agents-md` for the setup. Manual install steps stay in the README.
- `incident-postmortem` skill: writes a blameless postmortem from the facts in the incident window, with a sourced timeline, the trigger and any latent defect traced back to the commit that introduced it, impact, actions and a recommendation for each finding; declines to blame people and keeps personal data out of the report. Four evals on the sandbox `incident` and `services` scenarios.
- `pr-review` skill: reviews a pull request or branch against the repository's own rules (correctness, security, tests, scope, conventions), with a script that finds usages outside the diff the change can break; verifies each finding and reports a ranked table, or says the change is ready. Five evals on the sandbox `review` scenario.
- `package-manager` skill: migrates a project to another package manager (Poetry to uv, npm to pnpm) or adopts one when there is none, recommending the best fit with a criteria table; keeps every dependency version, updates scripts, CI, containers and docs, and leaves one lockfile. Python and JavaScript for now, other ecosystems in a to-do list. Four evals on the sandbox `python-poetry`, `python-pip` and `deps` scenarios.
- `dependency-update` skill: updates dependencies in small steps (security fixes first, patch and minor in groups, each major alone after reading its breaking changes), runs the checks after each step, commits what passes and reverts what breaks; a reference table covers the commands of fourteen package managers. Four evals on the sandbox `deps` scenario.
- `agents-md` skill: creates or updates a repository's `AGENTS.md` from facts a script gathers (agent files, manifests, declared commands, CI steps, installed skills, git habits), verifies commands before writing them, keeps the owner's text, always fills the `## Git workflow` section the other skills read, and adds only the optional rules the installed skills use. Five evals on the sandbox `no-rules`, `deps` and `integration-dev` scenarios.
- `design-doc` skill: turns a feature or system request into a short design before code (requirements with numbers, two or three options including the simplest, a recommendation, interfaces, failure modes, security, rollout and a plan of small pull requests), saved as a draft where the repository keeps designs. Four evals on the sandbox `services` and `trunk` scenarios.
- `architecture-review` skill: maps an existing system or a proposed design (Mermaid diagram, components, data, trust boundaries) from a cheap repository inventory script, then reports up to ten ranked findings with evidence and the smallest fix, using a checklist across security, reliability, data, scalability, operability, maintainability and cost. Four evals on the sandbox `services` scenario.
- `docs-sync` skill: finds the documentation a change left out of date from the diff, with a script that greps only the matching lines, and updates it or only reports it; never edits an accepted ADR. Four evals on the sandbox `docs` scenario.
- `fix-with-test` skill: reproduces a bug with a failing test, commits it, then makes the smallest fix that turns it green, with four evals on the sandbox `bugfix` scenario.
- `task-flow` skill: takes a change from branch to pull request following the repository's `## Git workflow` rules, with `safe` and `auto` modes, tasks read from a key or link when the agent can reach the tracker, rebase or merge updates after a merge, a script that reads only the workflow section, and seven evals.
- Design principles for every skill in `CONTRIBUTING.md`: spend few tokens and steer the agent to good coding practices.
- Repository foundation: README with install steps per agent, MIT license, contributing guide, pull request template and CI that validates every skill against the Agent Skills specification.
